# 金融行业参考上下文

草案 v0.5 · 供审阅。这里是金融行业的知识与方法入口，可用于查来源、拉取资料、筛选材料、抽取事实、理解专业问题，也可用于造题、演化与验证。**使用本 skill 不意味着必须造题或输出任务包。**

## 行业定义与工作对象

金融工作围绕资金的配置、定价、融资、风险、核算与履约展开。输入通常是财务披露、交易与产品条款、市场观测、监管规则及经营资料；专业产物常见模型、台账、审查意见和可复核的决策依据。

材料里的金额始终依附于主体、期间、币种、单位和范围。披露事实、管理层预测、评级意见与情景假设承担不同角色。真实亏损、勾稽差异和条款冲突不天然等于低质量材料，可能正是有价值的分析对象。

## 常见问题与材料关系

| 领域 | 常见专业问题 | 通常需要的材料 |
|---|---|---|
| 财报、审计与权益分析 | 盈利变化从何而来？现金与利润差异能否解释？重述影响多大？ | 报表、附注、分部披露、审计意见、更正公告 |
| 信用、债券与贷款 | 债务何时到期？担保是否重计？契约或偿债能力如何变化？ | 募集说明书、受托报告、财报、债务与担保表 |
| ABS、REITs 与项目融资 | 现金如何分配？触发条款是否生效？项目收益能否覆盖支出？ | 计划说明书、资产池、运营报告、分配条款 |
| 基金与资产配置 | 收益、风险与持仓变化由什么驱动？ | 净值、持仓、基金报告、基准及产品约定 |
| 银行、保险与精算 | 资本、拨备或偿付能力变化来自哪些口径与风险？ | 监管披露、资本表、偿付报告、模型假设 |
| 衍生品与交易风险 | 保证金、结算和敞口在情景变化下如何联动？ | 合约规则、行情、持仓、结算与风险参数 |
| 投行、并购与估值 | 交易假设是否一致？对价、调整项与敏感性如何复算？ | 交易文件、估值说明、问询回复、预测与财报 |
| 宏观与行业研究 | 结论是否受统计口径、发布时间和修订影响？ | 统计公报、时间序列、口径说明、行业数据 |
| FP&A、税务与财资 | 预算差异、税务调整或资金计划是否完整一致？ | 预算/实际、科目映射、税务规则、经营和现金资料 |
| 合规、披露与特殊资产 | 义务是否履行？风险暴露与资产回收假设是否有据？ | 监管规则、处罚/问询、公告、处置及重整文件 |

完整的 20 类工作及其资料组合见 [来源索引](references/sources.md)。这里的常见问题帮助理解材料能力，并不是要求用户先选择题目。

## 造题的通常流程

仅在需要造题时采用以下路径。工作流调研与资源库建设是独立的准备工作，不在这条路径内；造题时直接使用它们的产物。

1. **确定任务与材料**：优先从[任务类型库](references/workflow-research.md)取一张 `verified` 卡（或沿 `fusable_with` 取一组关联卡），按卡上的 `input_data` 从资源库选材料并盘点。只给了 `input-data/` 时，以材料为起点盘点真实文件、实体、期间、口径与可用事实，再对照任务类型库确认它对应哪项真实工作。
2. **发现问题**：在卡定义的工作范围内，从材料中的差异、关联、约束和可计算关系确定具体问题；无卡时提出 2–3 个候选任务。按输入覆盖、专业工作量、产物价值与可验证性比较，由 agent 自主选择；默认产出一道题。
3. **界定工作**：由 agent 确定角色、业务目标、时间点、口径、必要的显式假设和交付文件。显式用户约束可缩小空间，但不是造题前提。
4. **编写 instruction**：用委托人的职业工作请求说明目标、输入、必要业务假设和交付要求。题面与可见输入不承载出题过程、评分实现或反复的演练免责声明；口径与证据边界用正常业务定义表达。详见 [任务设计](references/task-design.md)。
5. **形成完整任务包**：按 [交付契约](references/output-contract.md) 组织输入、私有证据、真实参考产物、评分、环境与谱系。请求 Harbor 等 runner 交付时，制作该运行时可解析的原生环境、参考解和测试入口；设计清单不能代替可启动环境。原始材料不足时换问题或收缩范围。
环境、参考解与评分的具体构造方法分别见对应 references；批量调用按批次方法冻结上下文和执行门禁。

6. **验证与演化**：复核取数、公式、容差和合理替代解，并按授权执行环境、参考解、空白基线和实质错误挑战。分别记录包解析、真实 reward、评分覆盖、资源清理及独立模型试解；oracle 通过只说明参考解和执行评分链通过。需要更多题时读取演化方法；变更同步更新材料与评分，已接收版本保留。详见 [验证](references/verification.md)。
