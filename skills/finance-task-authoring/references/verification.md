# 金融任务验证与发布

仅做材料质量复核时使用 [通用筛选](common-screening.md) 与 [行业筛选](screening.md) 即可。本页用于题目与评测验证，遵循 [原生 Harbor 交付契约](output-contract.md)：检查 instruction.md、task.toml、environment 输入与工具、solution 和 tests 的真实入口。agent 初始 `/workspace/output` 为空，私有参考与审查记录保持隔离。

## 先验证题，再评价 agent

| 层次 | 检查 | 留下的证据 |
|---|---|---|
| 材料 | 文件可打开；必需表格和附件完整；版本、cutoff 与主体正确 | manifest + 页面抽查 |
| 事实 | 每个关键 criterion 都有事实和定位；单位及期间一致 | evidence coverage |
| 参考计算 | 独立重算、勾稽、舍入容差和边界情景 | reference calculation log |
| 交付物 | XLSX 公式和依赖可用，DOCX/PPTX 可读、引用真实 | artifact report |
| 环境 | 干净启动可打开并编辑原件；输入哈希一致 | environment smoke log |
| 评分 | 正解与合理替代解通过，指定错误被识别 | verifier mutation report |

## 必做的反例

- 金额单位乘/除 1,000；百分数和小数混淆；负号反转。
- 拿错期间、母公司替代合并、重述前替代重述后。
- 债务重复计算，漏担保或补救期，现金流瀑布优先级错误。
- 结果数字对但公式硬编码、情景变化不联动。
- 无来源的漂亮备忘录、伪造页码、引用不支持结论。

每条反例指定应失败的 criterion；不要求不相关检查同时失败。容差用原始精度与业务意义定义，不把同一固定容差套所有指标。

## 独立试解

从 agent 可见文件开始，不读取私有答案。可采用另一名审核者或另一个独立运行；记录输入哈希、模型/工具版本、时间、步骤与产物。试解失败先定位材料、题面、环境、验证器或能力问题，再调整题目。

不改良验证器去迁就错误答案。用合法替代结果和真实错误样例一起回归。人工判断 rubric 先双人/独立复核小样本以校准分歧；没有开展就标为待执行。

## 原生 Harbor 交付与执行

用户要求运行包时，先核对实际安装的 Harbor 版本、模型和入口，按 [交付契约](output-contract.md) 制作原生包。用安装版本解析 `task.toml` 和完整任务目录；TOML 可读或目录齐全只算静态检查，不能代替 Docker 中环境启动、参考解执行和 verifier 运行。

环境构建上下文只包含 agent 必需的输入和工具。参考解、答案、tests 和评测证据由 runner 在各自阶段提供，不烘焙到 agent 镜像。为业务输出声明真实产物收集路径；采用独立 verifier 环境时，实际核验输出能恢复到测试所读路径。工作簿使用真实公式重算，并以独立临时 Office profile 避免并发实例互相占用配置。

检验工作簿情景联动时，在独立副本中扰动输入并强制重算；处理导出文件的公式缓存和重算标志，确认重算结果随输入改变。直接读取缓存值，或只检查单元格有等号，都不足以证明公式依赖有效。

评分入口对有效评阅写出约定的 reward 和分项报告；空输出和不合格交付可明确得零分。脚本、可信输入、重算或 judge 通道故障另写失败报告，并清除旧 reward，避免被 runner 误认为有效任务分数。核对安装版本怎样处理退出码和 reward 文件。用 oracle、nop、实质错误及合理替代产物验证评分方向，记录被影响的 criterion 和实际 reward。检测应针对财务关系、口径、依赖和证据，不能靠词语出现、整份参考文本或固定版式判断专业正确性。

自由文字的证据解释、因果判断和可执行建议若由人工或模型评审，分项报告保留自动分、已评审分和 pending 项。外部评审记录绑定本次产物、输入及评分版本的哈希，附 criterion 判定与依据；哈希用于防评审后内容变化，不代替实际阅读，也不构成仅认可参考文件的白名单。尚未评审部分不能默认为满分。

自动检查只覆盖某项事实或公式时，将其结果作为该 criterion 的上界，并说明待评阅的状态解释、引用支持或正文一致性。真实评阅按同一 rubric 结算，避免把上界与完整评阅分重复相加。状态文字若没有公开的业务枚举，按实际数值和语义判断，接受有依据的不同表达。

评分 reviewer 只接收职业请求、可信材料、实际候选产物、rubric 和客观检查结果，不接收“oracle／错误解／替代解”等案例标签或预期 reward。预期结果由协调记录另存，用实际盲评分核对；正确参考也可能有实质缺项，不能因其来源自动给满分。向外部模型发送材料遵守当前具体授权，未获准时使用已授权的独立评阅渠道。

保存每次运行的版本、镜像摘要、参数、日志、reward、输出和清理证据。Docker、Harbor、rsi-forge 的运行与共享资源使用遵守当前授权和协调配置；只回收本次标识的资源。分别报告包解析、环境/执行链通过、评分挑战通过和独立模型解题情况。oracle 和 nop 不产生独立模型完成率。

## 建议的首批质量采样

先从 50 个金融材料包试采，按工作族、格式和复杂度分层；这是起步计划而不是实测结论。记录：关键事实覆盖率、材料补齐成本、误收/误删、完成率、验证器误判、每道有效题的制作和运行成本。

## 发布记录

`private/evaluation/validation.json` 为每项记录 passed/failed/not_run、实际执行者、时间、证据和版本。分开保存以下验收层：

- `harbor_execution`：实际解析、镜像与干净环境、参考解和空白基线执行、产物收集、真实 reward 及资源回收。
- `grading_calibration`：关键职业 criterion 实际评分、实质错误识别和合理替代解接受；专业判断的真实评阅通道、完整分项和故障行为已有证据。
- `independent_solver_rollout`：解题者从可见输入独立完成任务的能力实验，单独记录模型、工具、轨迹与结果。

必需材料、参考计算、真实环境执行和关键评分挑战均通过后，可以将原生 Harbor 交付标为 validated，并明确验收范围是执行与评分。独立模型试解未运行则该层仍为 not_run，时间和证据为空；它不阻止已完成的 Harbor 交付验收，也不能据 oracle 推断模型完成率。未实际运行或评分仍不完整的包保持 draft。本指南本身不宣称具体题目已通过这些门槛。
