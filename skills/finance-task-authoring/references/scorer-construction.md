# 评分器构造

目标是评价实际交付的专业质量。先定义证据和可接受答案范围，再实现抽取、检查与聚合；读取验证方法确定本次需要运行的校准范围。

## Rubric 与客观检查

每项有稳定 criterion ID、最高分、业务要求、支持证据、评分方法与部分分标准；总分与权重可复算。将客观事实/计算/文件要求与开放判断分开，同一缺陷的扣分范围清楚，必要的关键错误上限明确。

为产物实现格式感知的抽取器：工作簿读取公式与重算值，文书读取段落/表格/修订位置，CSV/JSON 校验实际语义字段。先建立可信输入与独立控制值，再比较候选的范围、单位、日期、计算与引用；文件存在、关键词命中或字段形状仅是完整性检查。格式与布局元数据读取候选原件，计算值可来自明确标记的重算副本。

解析失败或缺交付按 rubric 给分并保留理由；评分依赖失效、模型响应不完整或协议故障是 `verifier_failure`，不伪造成候选零分或满分。运行前清除旧 reward；只有完整有效评分才写 `/logs/verifier/reward.txt` 或 reward.json，并写分项报告。

## 专业评阅通道

评阅请求包含题面、可信输入、实际候选内容、必要原始页面/图像、rubric、客观检查证据及评分规则。保持事实的原件定位，尤其数字密集 PDF、复杂表格、图形与版式；抽取内容不足时补相应原始页面，不用黄金答案补候选证据。评阅者不见 oracle/挑战标签、预期分数或作者对该候选的结论。

密封请求记录内容哈希、候选字节身份与来源；保存实际发送体、真实模型响应、模型 ID、终止状态、usage 和分项理由。校验 criterion IDs、有限数值、分数边界与证据。协议需要时可把严格合法的数字字符串转为同值数值并记录转换；不能修正模型含义或虚构缺项。流式请求以完整终止事件为成功，ping 不是完成，读取与阶段总时间均有预算。

评分聚合代码对客观上限、语义分、关键错误 cap 的先后关系负责，报告能解释最终 reward。对允许的替代解和击中主要能力的实质错误运行少量针对性校准；重复全量评分应有新的变更或疑点依据。

## 缓存、费用与故障恢复

同一任务多次评分时，将稳定的题面/输入/rubric 放在前缀，候选及动态证据放后缀，按供应商支持配置缓存边界与 TTL。以实际 cache creation/read usage 判断命中；格式稳定的测试不能证明真实跨候选命中。一次性请求是否建缓存取决于后续复用预期。

解题与 judge 的调用分开记账，保留普通输入、缓存写入、缓存读取、输出 tokens 和实际调用数；未知 usage 保持未知，价格估算与供应商账单分开。批次配置限制并发、最大轮数、阶段超时和重试次数。

若服务已完整返回但本地发布失败，可校验当前请求与保存请求完全相同、候选哈希/模型/原始完整响应一致后恢复本次评分，注明 `new_model_call=false`。恢复只复用同一次完整响应，不跳过模型评分、不使用历史答案白名单，也不把局部前缀相同当作整个请求相同。
