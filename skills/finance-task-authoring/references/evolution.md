# 金融任务的 self-evolve

仅在需要扩展已有题目时使用。以已有任务包与新 input-data 为输入，由 agent 选择有专业意义的变体轴；用户不必逐题给问题。所有变体遵循 [交付契约](output-contract.md)，更新 instruction.md、lineage.json 与 private/evaluation。

## 从种子到变体

先固定种子的业务动作、输入契约、证据结构、可评分产物和 split。记录 `parent_task_id, root_seed_id, material_cluster_id, mutation_type, changed_facts, changed_constraints, expected_new_work, split`。

| 变体 | 怎样做 | 要重建什么 |
|---|---|---|
| 题面表达 | 同一业务需求改表达或角色措辞 | 检查约束未改变；标为表述变体，不能算结构新题 |
| 材料替换 | 换另一主体、年度或同类产品真实文件 | 全部事实、口径、计算、引用与 rubric |
| 口径变化 | 合并改母公司、重述版替换旧版 | 主体范围、比较期与桥接计算 |
| 情景变化 | 给定收入/利率/回收率或契约阈值变化 | 明确假设、触发条件与敏感性结果 |
| 工作链扩展 | 从单期复算扩为多期桥接或多个债务来源去重 | 输入完整性、依赖图和检查项 |
| 条款反事实 | 在明确标记的任务设定中改支付优先级等 | 一致更新条款、现金流、通知与结果；原件留存 |

## 一次迭代的执行步骤

1. 选择一种主要变化并写出它带来的新增推理，不同时随机改很多字段。
2. 获取新的真实材料；或将合成变更放在显式 scenario 文件，不能冒充发行人原始披露。
3. 更新受影响事实和所有下游计算，运行勾稽、单位和现金守恒检查。
4. 重写题面、rubric 和合法替代方案，重建 evaluator 私有包。
5. 从干净工作区试解并比较错误类型；报告成功率、耗时、token/工具成本时附实际样本量。
6. 去重检查通过后发布。新增题的难度标注先为设计意图，取得 rollout 数据后再校准。

## 防止同源泄漏

先按主体—事件—材料家族分组再分 split。同一种子的所有变体、同一交易不同版本、同一事实的改写都在同组。公开 benchmark 仅借鉴机制；直接复用其样例应标来源和用途，不进入声称独立的新测试集。
