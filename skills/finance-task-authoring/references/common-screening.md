# 通用材料筛选规则

## G01 · 找到原件，留下出处

让每份材料都能追溯到发布者和原始版本。

- 保存发布页与原件 URL、发布机构、获取时间和文件哈希；从正文核对标题、材料类型与版本，不以链接名称代替核验。
- 网页正文和附件一起归档，标记公开使用与再分发范围。

示例：上市公司公告链接关联原始年报 PDF；转载稿只作发现线索。

保留记录：source_manifest.json + 原件

## G02 · 确认材料可读且完整

把内容缺损和解析损失在入库时解决。

- 核对实际文件格式并尝试打开；网页只抽取正文，检查附件、表格和逐页文本覆盖。下载成功与文本长度都不能单独证明材料完整。
- 对乱码、重复正文及无文本页面分类处理；关键内容回看原页，合法空白页不机械剔除。
- OCR 作为连接原件的派生层保留定位和置信信息；金额、符号、脚注与条款引用在进入关键事实或评分前回看原件。

示例：OCR 把“(1,200)”识别成“1,200”时，先修复符号再入事实表。

保留记录：解析质检记录 + 原页定位

## G03 · 按对象组包，按版本去重

用同一项目的一组文件支持工作流程。

- 结合原件哈希与规范化正文去重；同一材料的不同格式只计一次，修订版保留替代关系，语义近似另行复核。
- 用主体代码、项目号、案号、产品代码和日期做关联；明确同项目与仅主题相似的材料关系。

示例：招股书、问询、回复、审计报告属于一组；新版本替代关系单独记录。

保留记录：bundle_manifest + 版本关系

## G04 · 锁定任务发生的时间

区分业务期间、公开日期和法律效力日期。

- 先写任务 cutoff，再筛当时已知的材料。
- 把后来的判决、兑付结果或更正结论按任务目的放到评测侧。

示例：事前信用判断只使用截止日已公开信息；事后复盘可以显式使用后续公告。

保留记录：as_of + published_at + valid_from/to

## G05 · 检查能否支撑交付物

材料质量取决于要完成的专业任务。

- 列出每个交付物必需的输入字段与来源。
- 缺关键输入时补包、缩小问题，或明确改为材料缺口识别任务。

示例：只有基金前十大持仓时，可以做披露核查；完整组合回测需要完整持仓。

保留记录：required_facts 覆盖表

## G06 · 提取事实，也保留分歧

建立能被验证的证据索引。

- 把事实、机构意见、当事人主张和待核对冲突分别记录。
- 每个事实关联原件、页码或单元格、单位、对象与时间。

示例：负利润、非标审计意见与文件冲突可能是高价值输入，应保留并分类。

保留记录：evidence.json + conflict_log

## G07 · 让题目能区分能力

从职业动作出发设计交付和评分。

- 要求分析、对账、修订、建模等实际产物，并检查内容。
- 金标准、计算中间值和评分程序独立放在评测侧；按材料家族切分数据集。

示例：改几个公司名不构成新题；同一案件及其所有变体进入同一个数据划分。

保留记录：task.json + rubric + lineage

## G08 · 试做，再校准筛选规则

用产物和错误样本检验入库标准。

- 独立解题，检查所有关键评分项是否有足够材料。
- 用错误单位、错误版本、虚构引用等反例挑战验证器。
- 首批按行业、格式、材料复杂度分层人工抽查，记录误收与误删。

示例：文本流畅但财务口径错，或法律结论正确但证据虚构，都应被对应检查识别。

保留记录：validation.json + 抽查记录
