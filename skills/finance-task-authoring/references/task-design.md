# 金融材料驱动的任务设计

## 从 input-data 发现题目

用户给的是输入材料，出题 agent 负责提出问题。先实际读取目录中的文件和样本页，不从目录名猜测内容。保存文件清单、哈希、可解析性、主体/事项、时间/版本、关键关系与缺口。查来源或补材料是独立能力，不是每次造题的默认前置步骤。

从可用证据提出 2–3 个候选方向，每个记录：业务问题、所需输入、已有证据、缺口、预期交付、评测办法。按材料充分性、专业价值、所需工作量和可验证性排序；明确阻碍可解性的缺口优先淘汰。由 agent 自主选题并记录理由，**不要把候选列表返回给用户要求先选一道才能继续**。

如果用户已给约束，把它用于筛选候选；没有约束就依据材料自行决定角色、问题、instruction、文件格式与工作区。默认一道题。材料不足以支持首选问题时换候选或收缩范围；只有没有任何可成立任务时，交付具体缺口报告并请求必要材料。

外部资料扩展按当前授权范围执行；若未要求扩展，优先使用现有输入。预算、头寸、现金及压力参数用业务场景文件定义，使委托目标和计算前提明确。人工构造步骤、采集过程和材料来源角色记录在私有 provenance；场景参数不得改写原件事实或被描述为官方披露。

## 原材料就是 input-data

**任务输入就是采集到的原件本身。** `raw/<source_id>/<document_id>/original.*` 里的 PDF、DOCX、XLSX、ZIP、HTML，就是喂给解题 agent 的东西。造题不产出"更干净的输入"。

`parsed/`、`ocr-pages.json`、`text.txt`、抽取出的表格，都是资源库自己的阅读副本和账目。它们的用途只有两个：出题时自己读懂文件、以及留档说明这份原件读起来是什么样。**它们不进任务包，不是 input-data。**

不许为了"让输入更规范"而做的事：

- **重打**：把原件内容抄成一份新 PDF、新 Word、新 Excel 当输入。抄一遍就丢掉了原件里真实存在的排版、合并单元格、打印区域外内容、扫描页、未签模板与占位符——而这些恰恰是专业工作要处理的东西。
- **清洗**：删掉重复表头、补上空白单元格、统一单位、修正原件里的笔误。原件长什么样就什么样，脏与乱是材料的属性，不是缺陷；已记录的原件问题（未签模板、币种单位混用、封面日期与披露日不一致）留在材料里，由解题者去发现。
- **补造**：公开材料缺的客户内部输入（批准模型与预算、逐笔授信/现货/账户记录、原始试算平衡、诉辩与证据卷宗、数据室索引、真实债权凭证）**不补造、不伪造、不用公开材料冒充**。缺口就是缺口，写进覆盖表。
- **派生当输入**：OCR 结果、文本抽取、你自己整理的汇总表，都不作为任务输入提供给解题者。
- **为过校验器而加工材料**：资源库校验器对 `parsed/`、`ocr-pages.json` 的要求属于资源库台账，不是造题的前置条件。校验器报的是账不平，不要用"顺手把材料处理一遍"来消掉它——那是在给账本对账，不是准备题目。

**缺输入的处置顺序**（从优到劣）：换一张材料能自足的卡 → 收缩题面范围，只考公开材料覆盖得住的部分 → 把缺口作为题目内容本身（要求解题者指出还缺什么、为什么关键）→ 交付缺口报告，不硬做。

底线：`input-data/` 里的可见文件，与 `raw/` 里的原件在内容和格式上一致，只有路径和命名按任务环境需要调整。这条映射记在 provenance。

## 材料包：组合合理性

选题确定后，核对材料包的**组合**是否合理——不是体积，而是三条性质：

1. **功能必要性**：每份文件都有职业流程上的功能。判定：删掉该文件，交付要求是否仍能从其余材料合理完成？是则它不必要。
2. **集合自洽性**：期间、口径、主体边界、单位、版本能相互对上。冲突与差异须是**真实材料本有的**（待核实的勾稽差、条款冲突、重述前后），不是作者制造的。
3. **职业形状**：文件组合是真实从业者手上会有的东西。审计底稿像底稿，投研材料像投研材料。

**禁止"作者添加剂"**：为让某事实易于查找而补的方便文档、为讲清口径而加的说明文件、为增加难度而加的障碍文档。这些不是真实工作流的一部分，也是"无谓的解读和处理"。

反过来，**原始材料中已存在的模糊性、勾稽差异与条款冲突应当保留**。真实的亏损、差异与冲突不天然等于低质量材料，可能正是有价值的分析对象。

CUA 场景下，Dockerfile 中安装的工具必须对应真实的打开/编辑/重算/导出需求；仅仅把 PDF 放到桌面不构成高质量 CUA 任务。

## 难度从哪来

**难度来自材料规模、勾稽层数、口径冲突数与约束耦合度，不来自把时间预算压到刚好不够。**

两小时（7200 秒）是长程题的参考上限，`[agent].timeout_sec` 应与断言数量、材料规模、预期工作项数相称。**不承担难度制造功能**——用预算饥饿制造难度会同时产生两个后果：候选超时归零、以及"跑得慢"与"做不对"在数据上不可区分。

题面应当要求**分批落盘**，让产物在过程中逐步累积。理由是评分只看终态存在的产物，不区分"完成"还是"超时"；增量落盘使"做了多少"与"写了多少"解耦，个别环节卡住不会导致已完成的工作全部丢失。

## 将选择落成文件

选定后按 [交付契约](output-contract.md) 实际生成文件夹与 `instruction.md`。给解题 agent 的指令和出题过程分别存放；前者只包含工作请求、输入、约束和交付要求，后者留在私有作者记录。

制作参考产物、证据索引和断言契约，再验证可解性与评分。原始 `input-data` 只读使用，把选中的输入复制或规范转换到任务环境，保留映射。源材料未覆盖的领域不硬塞评分项。agent 初始输出为空，参考资源只用于隔离的 solution 阶段；评测事实和代码由 tests 阶段提供。

## 金融任务的专业关系

- 财报：表格与附注取数 → 单位/期间/范围统一 → 勾稽 → 跨期桥接 → 有依据的解释。交付可为公式工作簿与短备忘录。
- 信用：债务/担保去重 → 到期和条款复核 → 明示假设下的现金压力情景 → 风险与缺口台账。
- 结构融资：条款矩阵 → 支付顺序 → 触发与情景 → 分配和现金守恒检查。缺资产池字段时改做条款核查，不编造现金流。
- 投行/审计：同项目跨文件核对 → 差异台账 → 计算调整 → 问询或审阅产物。不要把未实施的尽调写成已完成。
- 监管/税务/精算：先确认规则版本和输入充分性，再确定合理计算边界与交付表。

## 金融 instruction 的重点

明确分析时点、期间、合并/母公司范围、货币与单位、调整或情景假设。口径本身需要判断时，要求比较并论证，不以未公开的隐藏口径判错。关键计算要求保留公式和原件依据；若本题考查数据整理而非建模，则按实际业务选择 CSV/台账等产物。

题面应当像投研经理、基金财务负责人、风控负责人或客户团队发出的实际工作委托：先说明决策和需要交付的结果，再给材料与必要定义。审查 `instruction` 之外的全部可见文件，移除作者标签、合成步骤、答案方向、评分权重及仅为防御性表述而加入的"培训演练／本题不是／不要声称"。风险和缺证判断属于工作内容时，以业务动作表达，例如说明证据支持程度和所需补件；不要预先把结论写给解题者。

机器可读字段和表格应当服务于审阅、复算或后续业务交接。需要结构化证据和状态时公开字段含义与必要粒度，避免为固定金标准坐标、checker 参数或全文比对增设无职业用途的文件。允许工作簿布局、公式表达和措辞发生合理变化。

修订已有题目时，同时审查输入充分性、时间与口径、公式依赖、原始答案角色、参考产物和评分。文案自然不代表任务已修复；受影响的事实、输入、参考、断言与反例应一起更新。保留已接收包，另建有父题谱系的新版本。

## 评分维度与断言

评分维度示例：取数与口径 30、公式与勾稽 35、业务判断与证据 25、产物可用性 10。**这些权重是 criterion 层面的设计起点，不是经验验证结果。**

实际 reward 由 [评分器构造](scorer-construction.md) 的断言契约结算：维度决定 criterion 划分，criterion 之下拆出**互相独立**的断言，断言总数构成标尺 `S`。

因此设计阶段就要估算断言数：**目标 20–50 条**。少于 20 条时全对天然接近 1.0，没有区分空间，应通过增加勾稽环节、扩大材料范围或深化口径判断来提高分辨率——而不是简单地给同一批数值加重复校验。

数值采用业务容差与精度规则，解释采用证据约束的 rubric。特别记录合法替代口径及其成立条件。

## 交付前自问

- 去掉原始材料后，任务是否还能靠常识套话完成？删去关键文件后是否仍能通过评分？如果是，重做业务动作或评分依据，使材料真的必要。
- 材料包里有没有我加进去的辅助文档？有则删掉或说明其职业功能。
- 题面公开的交付要求与断言集合是否一一对应？有没有断言检查了题面没要求的东西？
- 断言是否互相独立？能否被不完成实际工作的路径通过？
- 实际断言数落在 20–50 区间内吗？不在时是材料/工作链不够深，还是断言拆得不够细？
