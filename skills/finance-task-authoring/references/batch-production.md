# 批量生产与无人值守验收

批量调用以冻结的上下文和可查询任务目录推进。每个 worker 从 input-data 自主设计任务，基础要求来自 skill；任务类别、数量、运行权限和费用预算由本次批次配置决定。

## Worker 输入与谱系

提交冻结的 skill 版本、资源池索引、可用材料及哈希、已接收题目摘要、材料使用量、任务类别/动作/输出形式配额、验证范围和运行预算。worker 先原子领取资源组合/设计名额，完成前标记 reserved；过期与失败领取可释放，已接收任务保持不可变。共用来源不自动禁止复用，要比较实际证据范围和专业动作。

每个题目生成结构化 lineage：task ID/版本、父任务 IDs、source IDs/原件哈希/证据范围、材料角色、工作族、核心动作、交付格式、设计签名与 split group。相同实体/期间/条款段和相同核心动作的变体归入同组；通过索引和脚本查看资源覆盖、用量、近似题与配额，再选择未被过度使用的组合。只改文件名、公司名或数值不视为新的能力覆盖。

## 阶段与门禁

| 阶段 | 可核验交付 | 进入下一阶段的条件 |
|---|---|---|
| 材料与选题 | 输入盘点、候选选择、证据范围、lineage | 必需输入与业务口径可支持问题；领取及重复检查完成 |
| 构建 | 原生题面/配置、环境、参考解、评分器 | 包内依赖完整，静态 preflight 与 Harbor schema 解析通过 |
| 运行校准 | 环境 smoke、oracle、空输出、针对性错误/替代挑战 | 实际有效评分、关键能力覆盖、合理替代解可接受、资源回收 |
| 独立审阅 | 对最终包的证据/专业/运行审阅与内容哈希 | 缺陷修复，受影响验证重跑，审阅绑定最终包 |
| 接收 | 不可变包、版本/依赖、运行 receipts、索引 | 记录实际完成和 not_run 项；接收后修改产生新版本 |

需要测量 agent 能力时，另开独立 solver trial，隔离答案与私有评测材料。参考解通过说明执行评分链能工作，不等于模型解题通过。静态检查脚本只能证明结构和配置，不能证明环境能启动或专业评分有效。

worker 在失败时返回阶段、原因、相关日志、已用预算、已清理资源和可恢复位置；控制层只重试受影响阶段，达到重试/成本预算转为待处理，不靠持续聊天补齐任务定义。运行前后记录包哈希，收尾持久化结果并释放沙箱。资源获取、出题接收、运行验证和 solver 能力状态分别存储。

通用修复维护到相应 reference；企业案例、具体参数、页面集和校准候选留在题目或批次资料中，避免 skill 变成单批题目的操作手册。
