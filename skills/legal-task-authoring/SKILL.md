# 法律行业参考上下文

草案 v0.5 · 供审阅。这里是法律行业的知识与方法入口，支持寻找资源、拉取文件、筛选与抽取资料，也支持设计、演化和验证专业任务。**本 skill 提供参考上下文，不为每次调用预设最终目标。**

## 行业定义与工作对象

法律专业工作围绕权利义务、交易安排、争议解决与规则适用展开。其材料包括规范、合同、附件、往来记录、案件证据、裁判文书与监管文件；产物常见审查意见、修订稿、证据矩阵、研究备忘录及程序文件。

同一句话可能是当事人主张、证据描述、裁判认定或任务假设，不能混成无差别事实。规范要结合事项时间、法域、效力层级和程序阶段理解；存在合理分歧时，重点是依据与论证条件。公开判决可支持案例分析，不能自动当作完整的事前案件卷宗。

## 常见问题与材料关系

| 领域 | 常见专业问题 | 通常需要的材料 |
|---|---|---|
| 合同与采购 | 义务是否清楚？主文与附件冲突如何处理？修改是否联动？ | 合同、附件、澄清、补充协议、报价 |
| 诉讼与争议 | 哪些事实有证据？争点和要件如何对应？反方理由是什么？ | 已提供证据、往来、诉辩文书、适用规范 |
| 公司、证券与并购 | 授权、控制、披露与交割条件是否完整？ | 章程、决议、交易协议、公开披露 |
| 破产、担保与执行 | 债权范围、顺位、表决或清偿如何确定？ | 债权表、担保文件、重整/分配计划、裁判 |
| 知识产权 | 权利范围、版本、法律状态与争点怎样对应？ | 专利/商标记录、权利要求、引证、决定 |
| 劳动与行政 | 金额和期间如何计算？事实是否满足当时规则？ | 劳动/行政文件、工资工龄、送达、地方规范 |
| 数据、竞争与监管 | 行为触发哪些义务？流程与风险如何定位？ | 业务事实、协议政策、监管规范、执法材料 |
| 建设与不动产 | 工期、价款、变更与责任如何衔接？ | 招采、合同、工程附件、变更与结算 |
| 仲裁与跨境事项 | 条款、程序、法域和可执行性如何关联？ | 仲裁条款、机构规则、程序文件、相关法源 |

完整的 12 类工作、材料组合与来源见 [来源索引](references/sources.md)。问题空间用于理解资料和发现工作机会，无需每次都把它转成题目。

## 造题的通常流程

仅在需要造题时采用以下路径：

1. **盘点 input-data**：识别文件类型、主体、事项、时间、法域、版本、证据角色和材料关系。只提供判决时，优先考虑公开案例分析，而非假装拥有完整原始卷宗。
2. **自主提出与选择问题**：从真实条款冲突、争点、证据缺口或义务链中形成 2–3 个候选任务，比较材料覆盖、工作价值和可评测性，由 agent 选定一个；默认一道题，不要求用户预先定义角色或题目。
3. **构造专业工作情境**：确定有材料支持的委托背景、审查立场、事项时间、程序阶段和交付物。业务参数、计划目标及计算口径用正常工作底稿说明；材料构造过程放私有 provenance。缺证据时可设计证据盘点或补件工作。
4. **编写 instruction**：写成自然的职业请求，交代背景、要解决的问题、资料、工作动作和交付要求。实际路径与运行环境一致；必要事实、范围和计算口径在可见输入中提供。制作说明、训练身份、评分提示及与委托无关的防御声明留在私有记录。
5. **制作完整任务包**：按 [原生 Harbor 交付契约](references/output-contract.md) 制作 instruction、task.toml、实际环境与输入、可执行参考解和评分入口。评分包含客观检查与证据化专业 rubric，接受有依据的不同论证、措辞、布局和商业取舍。
环境、参考解与评分的具体构造方法分别见对应 references；批量调用按批次方法冻结上下文和执行门禁。

6. **验证并按需演化**：独立核验版本、引用、事实角色、日期金额、修订位置和交叉引用，在实际声明的环境中运行参考解、空输出、实质错误及合理替代挑战。开放判断的专业评分通道须实际执行并保存分项依据；变体同步所有受影响产物和评分。参考解校准与独立模型解题分别记录；未执行项保持 `not_run`。
