# 法律材料驱动的任务设计

## 从 input-data 发现题目

用户给的是输入材料，出题 agent 负责提出问题。先实际读取目录中的文件和样本页，不从目录名猜测内容。保存文件清单、哈希、可解析性、主体/事项、时间/版本、关键关系与缺口。查来源或补材料是独立能力，不是每次造题的默认前置步骤。

从可用证据提出 2–3 个候选方向，每个记录：业务问题、所需输入、已有证据、缺口、预期交付、评测办法。按材料充分性、专业价值、所需工作量和可验证性排序；明确阻碍可解性的缺口优先淘汰。由 agent 自主选题并记录理由，**不要把候选列表返回给用户要求先选一道才能继续**。

如果用户已给约束，把它用于筛选候选；没有约束就依据材料自行决定角色、问题、instruction、文件格式与工作区。默认一道题。材料不足以支持首选问题时换候选或收缩范围；只有没有任何可成立任务时，交付具体缺口报告并请求必要材料。

外部资料扩展按当前授权范围执行；若未要求扩展，优先使用现有输入。计算约定、业务参数、计划目标和条件预案放入可见工作底稿，以正常业务语境说明。采集、构造或转换过程记入私有 provenance；官方原件的身份与事实保持真实。

## 材料包：组合合理性

选题确定后，核对材料包的**组合**是否合理——不是体积，而是三条性质：

1. **功能必要性**：每份文件都有职业流程上的功能。判定：删掉该文件，交付要求是否仍能从其余材料合理完成？是则它不必要。
2. **集合自洽性**：签署版、附件、补充协议与规范版本能相互对上；主体、日期、条款号、法域一致。冲突与差异须是**真实材料本有的**，不是作者制造的。
3. **职业形状**：文件组合是真实从业者手上会有的东西。案件卷宗像卷宗，交易文件像交易文件。

**禁止"作者添加剂"**：为让某条款易于查找而补的方便文档、为讲清规范适用而加的说明文件、为增加难度而加的障碍文档。这些不是真实工作流的一部分，也是"无谓的解读和处理"。

反过来，**原始材料中已存在的模糊性、条款冲突与规范竞合应当保留**。条款间的矛盾、附件与主文的优先级冲突可能正是有价值的分析对象。

CUA 场景下，Dockerfile 中安装的工具必须对应真实的打开/编辑/批注/导出需求。

## 难度从哪来

**难度来自材料规模、义务链层数、争点数与约束耦合度，不来自把时间预算压到刚好不够。**

两小时（7200 秒）是长程题的参考上限，`[agent].timeout_sec` 应与断言数量、材料规模、预期工作项数相称，**不承担难度制造功能**——用预算饥饿制造难度会使"跑得慢"与"做不对"在数据上不可区分。

题面应当要求**分批落盘**，让产物在过程中逐步累积。评分只看终态存在的产物，不区分"完成"还是"超时"。

## 将选择落成文件

选定后按 [原生 Harbor 交付契约](output-contract.md) 实际生成 instruction、task.toml、环境、参考解与评分入口。instruction 是客户、采购、合规负责人或案件团队会发出的工作请求，给出背景、优先目标、资料和交付标准。出题过程、合成步骤、采集验证与评分权重留在私有记录。逐一审查所有可见文件，包括 DOCX 页眉页脚/批注、XLSX 说明行/隐藏内容、JSON 字段和解析文本前言，使业务材料与题面语境一致。

制作参考产物、证据索引和 rubric，使 environment/Dockerfile、solution/solve.sh 与 tests/test.sh 的真实路径一致。输入复制或转换到 environment/input-data，映射到 /workspace/input-data；输出到 /workspace/output。官方原件只读保留，转换记录和场景设定保存在 provenance。评分必需事实均在可见输入中提供。参考资源与 tests 由各阶段提供，agent 基础镜像只包含工具及输入。

## 法律任务的专业关系

- 合同：定义、主文、附件、优先级 → 义务链与冲突 → 指定立场下的修订 → 交叉引用复核。产物可为修订稿与问题台账。
- 争议：主张与认定分层 → 争点/要件 → 支持与反证 → 规范适用 → 可接受论证。只有公开判决时，选择裁判分析、类案对照或信息抽取任务。
- 公司/并购：主体与授权 → 披露与交易条件 → 风险或交割台账；输入不支持实质尽调时，明确工作限于文件核查。
- 履约/程序：义务条件与日期 → 期限和金额计算 → 行动日历或审阅意见；明示计算依据与日历。

## 法律 instruction 的重点

用工作范围和待核实事项自然说明证据缺口，避免反复使用“合成题”“培训演练”“本题不是”或与工作无关的“不要声称”。自然化不意味着把自建底稿说成官方记录，也不意味着补造缺失事实。

由材料决定审查立场、法域、事项时间、程序阶段和需要的规范范围。需要外部检索时明示范围与截止；任务可在闭集材料中完成时提供完整适用规范。缺事实可成为“需补充证据”的工作点，不把不存在的事实藏进唯一标准答案。

原始判决中的结果如已提供，任务就不能把猜出该结果当作主要难点。基于未来结论反向伪造事前卷宗也不能制造独立问题。任务价值可来自争点矩阵、反方论证、条款关系或实际修订。

## 评分维度示例

事实与引用 25、争点与规则适用 30、可执行修改/建议 30、产物可审阅性 15，可按所选任务调整。允许论证充分的替代路径；不同措辞、合理商业取舍或与实际裁判不同的合理论证不自动判错。关键客观事实与专业判断分开评分。

## 交付前自问

去掉原始材料后，任务是否还能靠常识套话完成？删去关键文件后是否仍能通过评分？如果是，重做业务动作或评分依据，使材料真的必要。涉及 CUA 时，应当存在可检查的打开、编辑、重算、批注或导出需求；仅仅把 PDF 放到桌面不自动构成高质量 CUA 任务。
