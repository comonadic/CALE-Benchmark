# 参考解构造

参考解是完整工作结果与可复现的生成入口，用于校准题目和评分器。它可以展示一种专业取舍，评分器仍需接受题目允许的其他合理结果。

## 证据到产物

1. 将原件中的事实或条款整理成私有证据账：文件身份与哈希、物理页/段/表格位置、事实角色、期间/版本、单位、原值与转换。场景假设独立记录，不能冒充原件事实。
2. 建立中间计算或论证结构，按题目交付要求生成真实可编辑文件。取数、公式、日期、义务或引用的依赖关系可复核；说明中的数字与底稿一致。
3. `solution/solve.sh` 从干净输出目录调用包内实现或复制完整参考产物，生成题面全部交付物。入口与依赖不引用作者机器路径。已完成静态文件可以成为参考资源，但仍需验证它们在声明环境中的使用与编辑。
4. 独立核查关键事实、计算与专业判断，打开或渲染产物，检查重算、版式和可编辑性。原始文件保存格式/布局身份；重算副本验证数值，分别记哈希。为每个 rubric criterion 记录实际产物中的支持位置，暴露题目缺口和评分遗漏。

## 校准与变更

在真实 Harbor 环境运行 oracle 并保存分项评分。发现缺陷先定位题面、原件、参考解、抽取器或 rubric 中的原因，再修改受影响部分；正确参考解获得少量模型扣分时保留真实分数并检查理由，不为追求满分改成迎合评阅者的答案。

选择与题目等价的不同措辞、布局、公式写法或有依据的商业取舍做针对性检查；对关键业务错误构造挑战，证明相关评分项确实下降。挑战资源不进入解题镜像，也不把挑战名称或预期得分送给 judge。

参考文件哈希记录身份与谱系，不能作为候选满分白名单。独立 solver 不读取参考解、私有证据与 rubric；oracle 校准和独立 solver 的表现分别报告。

## 行业核查重点

法律：复核法域、版本与生效时间、程序阶段、事实角色、要件和引证支持；规则、裁判认定、当事人主张与业务选择分开。
