# 法律资源获取与 reference 库维护

本页可以单独使用。目标可以是发现来源、试采、批量拉取、增量维护或整理原件，**不要求先有题目、instruction 或评测器**。网站目录、格式、规模与关联键见 [来源索引](sources.md)。

## 从来源到实际文件

1. **界定采集切片**：使用当前需要的领域、材料类型、时间窗、主体和数量预算。未指定细目时，先选择官方来源中有代表性、容易组包的一小批样本，列出可扩展范围；问题类型可辅助选材，但不必提前设计题目。
2. **探测获取路径**：从来源索引进入官方目录、检索页、附件下载或正式数据服务。验证分页、日期参数、附件链接、稳定 ID 和原始格式；把站点当前行为记录下来，不假设可访问页面一定支持批量接口。
3. **试采并验收**：先下载小批原件，保留响应格式、页面到附件关系及失败原因，核对文件真实格式、正文标题、主体、版本和关键字段；遇到附件重定向时保留发现路径与最终下载地址。采集成功率与有效包比例分别统计。
4. **增量拉取**：按日期或稳定 ID 分片，保存游标与断点，对暂时错误退避重试。凭 content hash 去重；更正公告和补充附件保留版本关系，不覆盖旧件。需要登录或数据服务的入口使用正常授权渠道。
5. **入库筛选**：先做 [通用筛选](common-screening.md)，再做 [行业筛选](screening.md)。记录通过、待补和不适用的具体原因；某个任务不能用的材料，仍可保留为其他用途的资料。
6. **持续维护**：新批次比对文件与版本，复查已变更来源；从已保存且核验通过的文件重新统计原件数、去重材料数和有效材料包数；失败项单列，重试日志与解析/OCR 副本不累加为采集量。目录里的规划数量不自动变成采集量。

## 推荐的资料组织

```text
reference-library/
  raw/<source_id>/<document_id>/     # 原件与抓取元信息
  parsed/<document_id>/             # 文本、表格、OCR；连接原件哈希
  packages/<material_id>/manifest.json
  catalog.jsonl                    # 文件级索引
  quality.jsonl                    # 筛选结果与复核依据
  runs/<run_id>/report.json         # 范围、断点、耗时、实际数量
```

可映射到现有库结构，不必为本 skill 迁移存储。单文件索引至少保留 `document_id, source_id, original_url, title, entity_ids, published_at, acquired_at, file_path, original_format, content_hash, version_of`；材料包记录关联键、文件列表、覆盖范围与缺口。

## 行业组包重点

- 规范按发文机关、文号、版本与效力区间关联；发布日期不等同生效日。
- 案号、上下审级、交易/项目号、申请号连接原件，保留同案或同项目的材料簇。
- 合同主文、附件、澄清和补充协议按签署版本及优先级组织；不能用同名文件替代确认。
- 判决中的证据叙述与实际证据附件分开登记，公开案例分析与事前法律工作使用不同材料视图。

## 单独采集时的完成条件

交付下载到的原件、索引、质量记录与本次采集报告即可。报告说明范围、实际数量、可用性、缺口及可继续使用的游标；不额外要求生成题目或运行沙箱。
