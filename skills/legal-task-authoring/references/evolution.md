# 法律任务的 self-evolve

仅在需要扩展已有题目时使用。以已有任务包与新 input-data 为输入，由 agent 选择有专业意义的变体轴；用户不必逐题给问题。所有变体遵循 [交付契约](output-contract.md)，更新 instruction.md、lineage.json 与 private/evaluation。

## 允许的变体轴

| 变体 | 新增工作 | 同步校验 |
|---|---|---|
| 题面表达 | 同一事项换表达 | 立场、请求与事实条件不变；标为表述变体 |
| 新案件/合同材料 | 相同业务流程遇到新证据和条款 | 重抽事实、证据、规范及参考意见 |
| 审查立场变化 | 从采购方切换供应商等 | 风险偏好、修改目标、可接受条款与评分重写 |
| 新附件/补充协议 | 处理优先级和交叉引用冲突 | 主体、日期、权限、义务链与最终版本 |
| 程序节点变化 | 从履约咨询到争议准备 | 当时可得证据、期限、可请求事项与规范 |
| 反事实条件 | 明示修改通知日、金额、责任上限等 | 事实链、日期、金额、文书与 rubric 一致更新 |
| 法域/时期变化 | 适用不同版本或地域规范 | 重新做法律适用分析，不能仅换法条名称 |

## 迭代流程

1. 保存种子谱系、案件/交易聚类与 split，写清本次变化及其业务意义。
2. 优先替换成真实、材料充足的新包。合成修改放在显式 scenario 文档，原始材料不改名伪装。
3. 根据变更更新争点—事实—证据—规范映射。检查每条结论是否还成立。
4. 重做修订稿、期限和金额计算及评分要点，添加合理替代论证。
5. 试解并检查是否引入无法从材料回答的问题。用错版本、漏附件和假引文反例做回归。
6. 对近似题聚类，记录新材料、新争点、新流程各自贡献；表面改写不要重复计算任务多样性。

同案文书、上下审级、同合同各版本及所有子题放在同一 split。判决文本改写不能消除对公开案件的记忆；通过新交付物、证据依赖和无输入试解评估记忆捷径。
