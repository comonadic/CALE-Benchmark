# 法律任务验证与发布

仅做材料质量复核时使用 [通用筛选](common-screening.md) 与 [行业筛选](screening.md) 即可。本页用于題目与评测验证，遵循 [原生 Harbor 交付契约](output-contract.md)：检查 instruction.md、task.toml、environment/Dockerfile、solution/solve.sh 与 tests/test.sh；输入和输出按声明的容器路径核验，私有记录与参考资源按角色隔离。

## 分层验证

1. **材料**：合同签署版、附件与补充协议相互匹配；案件证据角色明确；规范版本符合任务法域、事项日期和过渡规则。
2. **客观事实**：主体、金额、日期、条款号、引用真实且支持结论。计算期限时记录起算事件、规则、工作日/自然日和适用日历。
3. **专业推理**：按争点覆盖、规则适用、事实分析、反方回应和建议可执行性评分。对存在争议的法律解释列可接受替代路径。
4. **文书操作**：DOCX 可打开、修改落点正确，批注和 before/after 可审阅；条款定义和附件引用保持一致。
5. **环境**：从干净镜像打开原件并完成关键编辑/导出；私有评测文件不在解题工作区。

## 验证器挑战集

- 引用不存在的法条、真实条款但不支持本结论、真实案例的错页码。
- 把当事人主张当成法院认定，或把后来判决作为事前证据。
- 使用错误法域、错误规范版本、忽略过渡条件。
- 漏掉补充协议或优先级，修主文却漏改附件里的矛盾约定。
- 错算送达/起算日、金额基数或违约金公式。
- 文书语言专业但缺关键争点；另一份措辞不同、论证充分的合法答案。

错误样例应击中对应 criterion；合法替代答案应能通过。自动文本判断不确定时记录理由并复核，而不是给虚假的确定分。

## 人工与程序分工

程序负责文件、引用存在性、日期金额和结构化字段；专业判断用带证据的分项 rubric。评审者看到任务事实和评分定义，不将参考文书当唯一答案。先独立评审少量题，记录分歧并修订标准；这些是建议流程，未执行不能报告一致率。

## 试解与发布

独立试解只读 agent 可见包。记录事实缺口、法规检索边界、环境故障与题面歧义。材料不足时先补材料或收缩问题。

首批建议 50 个法律材料包，按工作族、文书形态、证据完整性分层抽查。统计有效包比例、关键证据覆盖、误收/误删、判分分歧与每道有效题成本。

发布记录包含原件哈希、规范快照、种子谱系、rubric 版本和实际验证报告。分开记录 harbor_execution（环境与完整任务生命周期）、grading_calibration（参考解、空输出、实质错误与合理替代的评分表现）、independent_solver_rollout（独立模型解题）。按用户要求完成前两层后，可验收 Harbor 交付；用户未要求的第三层可保持 not_run，不推断模型完成率。请求范围内的必需验证未完成时保持 draft；真实运行状态写入 private/evaluation/validation.json。

## 原生运行与专业评分校准

先用实际安装的 Harbor 解析 task.toml，再在声明的镜像中执行完整参考解、空输出及挑战。核验 agent 阶段的镜像、文件和挂载，确认仅含工具与可见输入；tests 和参考资源在相应阶段提供。原件、图表、办公依赖、字体、公式重算和文件解析使用可移植依赖，不能依赖作者主机私有库。

环境配方应从公开且固定的基础摘要独立构建，完整声明实际依赖；本机预建镜像标识放在运行 staging、宿主导入配置和验证 receipt。配方修订后区分旧镜像执行与新配方构建；比较实际工具版本、输入及评分组件，只复用有一致性证据的机械检查，不能把旧运行写成新配方运行。

客观检查报告传给专业评阅通道。逐项 rubric 评分需要实际候选内容、理由和输入证据定位；结构通过不能自动获得专业满分。语义错误挑战应击中对应分项，合理异策或等价公式应获得应有分数。图形或版式是核心证据时，评阅者要实际看到原页或产物图像，解析文字或作者摘要不足以替代图像核验。

专业通道可在独立 verifier 内执行，也可由明确配置的宿主 bridge 评阅离线容器产物。每个输出需重新评阅，保存请求、实际模型或评阅者身份、分项分数、理由和证据。请求摘要只用于绑定本次产物，不能作为参考答案白名单。凭据留在宿主；缺 judge、解析或检查执行失败、响应不完整均为 verifier 故障，不能伪造 task reward。

空输出判零前先核验可信输入快照的文件集合、摘要和可解析性；缺失或损坏的可信输入属于运行故障，不生成 reward。候选交付物的损坏 ZIP、XML 或不可读取内容属于交付缺陷，应保留实际文件摘要和客观失败证据。全部必需产物均不可读取时可判零；部分产物可读时继续按真实内容、缺件及损坏情况逐项专业评分。合法产物所需的解析依赖、LibreOffice 或实际检查执行不可用仍是运行故障。用有限、实质的边界案例验证这一区分，并保留改动前后的实际运行版本，不能把既往运行重记为新验证器执行。

保存 task 与镜像摘要、Harbor 版本、实际命令、trial/job、输出、reward、分项报告、耗时、清理及删除后确认。共享本地运行时按协调者的生命周期锁和资源范围串行执行，核验本次资源回收，保留其他任务资源。参考解与挑战是评分校准；独立模型解题另记，不能由 oracle 通过推断模型能力。已接收旧包保持不变，修订发新版本并保留父题和变更证据。
