# 评分器构造

目标是评价实际交付的专业质量，并产生**可区分难度、不可被套利**的标量 reward。先定义验证断言的覆盖范围与工作单元，再实现抽取、检查与聚合；读取验证方法确定本次需要运行的校准范围。

## 断言：reward 的计量单位

评分的基本单位是**断言（assertion）**，不是 criterion。每条断言是一个可独立复核的命题，对候选产物给出 `passed` / `failed`，并带稳定 `id`。

**断言必须互相独立。** 同一事实的不同表述、同一数值的重复校验、同一关系的多处引用**只能算一条断言**。对同一个量用三种路径算三遍是冗余，只增加分母、不增加区分度——它把 reward 推向饱和（全对即 1.0），正是"分数都上 0.9"的结构性成因。判断标准：**两条断言互换顺序或删掉一条，是否会改变候选完成度的高低排序？**不会则合并。

一致性检查用独立断言表达，不要为数值断言再叠一层重复校验。

### 断言的两个来源

| 来源 | 覆盖 | 判定方式 |
|---|---|---|
| 结果断言 | 终值、口径、单位、期间、结构、文件完整性 | 程序从可信输入独立重算并比较 |
| 依据断言 | 取数是否落在可信材料、引用是否真实存在、条款是否确实触发、公式依赖是否成立 | 程序在可信原件中定位并核对 |

**依据断言就是过程分。**过程分不是"叙述是否合理"，而是**候选声称的每一条依据是否真实存在、推导是否成立**。因此它仍然是客观判定，但只接受可定位的锚点：

- 候选给出中间量 → 独立算出该中间量并核对相等；
- 候选声称某条款触发 → 在可信原文定位该条款，核对存在且条件成立；
- 候选走了另一条合法路径 → 该路径须落在预先枚举的等价类内。

模型自述的 `calculation_trace`、理由文本、步骤说明**不作为得分依据**，只用于提示复核位置。

### 断言总数是难度参数，不是评分参数

断言总数决定评分分辨率：**更难的题配更多断言**，使每条断言代表大致可比较的工作增量。

- 目标区间：**20–50 条独立断言**。少于 20 条时全对天然接近 1.0，没有区分空间；超过 50 条时单条权重过小，噪声上升。
- 该区间是从批次实测分布取的参考值，**不是经验定论**；每批应记录实际断言数与 reward 分布，再校准。

## 聚合：绝对通过数

```
reward = P / S
  P = 通过的结果断言数 + 通过的依据断言数（绝对计数）
  S = 本题声明的固定标尺
```

三条规则，逐条有理由：

**1. 用绝对通过数，不用通过比例。**同一批次混装不同难度的题时，比例会抹掉难度差异——"难 10/20"与"易 2/4"比例相同，但前者需要多得多的工作。绝对计数保留这个差异。

**2. `S` 在题包内冻结，不用批次内最大值归一化。**按批次最大值归一化会让单个极端样本改变整批标尺，使候选的得分依赖于同批其他人，既破坏跨步可比性，也打开操纵通道。**`S` 取本题断言总数，写进题包并在评分时校验一致。**

**3. 报告缺失时回退，保证真解不为零。**断言报告缺失或不可解析时，回退到终态结果判定，**不判零**：

```
if 断言报告可用:  reward = P / S
else:             reward = 终态结果（0 或 1）
```

回退是防"真解被记零"的保护，不是宽容：**结构完整的候选不会因评分器自身故障而丢分**；评分器故障另有失败通道（见下）。

reward 上限为 1.0；`P` 可以超过 `S`（当断言数多于标尺时），此时 clamp 到 1.0 并记录。

### 关键错误 cap

存在会造成实质业务危害的错误时（拿错主体/期间、单位量级错、把未实施工作写成已完成、伪造引用），设 cap 限制该候选的最高分。cap 值必须：

- 由**结果断言**触发，不依赖评阅者自报；
- 在题包 rubric 中公开，与 criterion 的对应关系明确；
- 记录触发它的具体断言 id。

**cap 只能降低分数，不能提高。**它是上界，与 `P/S` 取较小值。

### 专业评阅的位置

开放式专业判断（论证质量、文件可用性、业务表达）通过独立评阅通道评分，且有两条硬约束：

**评阅分不能突破结果断言的上界。**每项 criterion 的最终分为：

```
criterion 得分 = min(评阅分, 结果断言上界)
```

**依据断言站不住时，相关评阅分同项扣减。**即：评阅不得为一条已被客观判定为错误的主张给正分。

评阅分与断言分**不重复相加**：断言覆盖的量由断言结算，评阅只结算断言覆盖不到的专业判断。

## 可接受解：覆盖范围靠枚举，不靠试解

"验证器包含所有可行解"无法用 rollout 统计证明——该命题不可证，且一批全高分的 rollout 不提供任何覆盖信息。落地形态是**构造式枚举 + 试解发现**：

**构造式枚举（确定性的，进验收门槛）**——每个合法变体必须得满分，每个错误变体必须低于阈值：

| 变体类别 | 要求 |
|---|---|
| 不同编码 | 同一时刻的不同时区表示、同一数值的不同单位写法、同一金额的不同精度 |
| 不同解法路径 | 公式串／操作数引用树／逐步算式；不同但合法的口径选择 |
| 不同布局 | 工作表顺序、列序、字段命名等互操作非必需的差异 |
| 合法替代措辞 | 论证充分但用语不同的文书 |
| 数值错误 | 单位量级、符号、期间、范围错误各一类，必须被对应断言击中 |
| 语义错误 | 数字对但公式硬编码；引用不支持结论；把主张当认定 |

每条变体指定**应被击中或应通过的断言 id**；不要求不相关断言同时失败。变体的实际运行状态记入验证记录。

**试解发现（统计的，用于发现问题）**——批量 rollout 承担的是：

- 发现**预料之外的合法解**：满分候选若被扣分，说明断言有假阴性，须扩枚举或修正断言；
- 发现**被接受的错误解**：低质量候选若得分过高，说明断言不足或 cap 缺失；
- 标定**难度分布**：实际 reward 分布用于调整断言总数与难度轴。

试解统计不进入验收门槛（样本量通常不足以支撑结论），只产出待处理项。

## 校准闭环：反复 rollout 直到 verifier 收敛

枚举表给出的是**上界**（作者能想到的变体），rollout 给出的是**下界**（真实模型实际走到的路径）。两者之间的差就是必须逐轮消掉的项。这是评分器构造的执行循环，不是发布前的一次性检查。

每轮做四件事，逐轮进行，直到退出条件成立：

1. **取候选池**：对同一题面批量 rollout，取得多个独立完整候选产物。要的是分布不是单例——每题至少覆盖不同能力档位。
2. **逐条 review**：每个候选读产物本身，判定两件事——**完成度**（真的做完了多少工作）与**合法性**（是否是有依据的正确解）。不要用 reward 反推完成度，reward 是要被校准的对象。
3. **按结果分诊**：按下表归类，每类有固定的处置动作。
4. **回写并重跑**：改动题面 / 断言 / 枚举表后重跑同一批，"发现问题"本身不算修复。

| 该候选实际是 | verifier 给出 | 含义 | 处置 |
|---|---|---|---|
| 合法完成 | 满分 | 正常 | 计数器 +1，用于标定难度 |
| 合法完成 | 被扣分 | **假阴性**——合法解被拦 | 该解**扩进枚举表**（作为正例保留，不删断言）；只有确认断言本身错误才改断言 |
| 错误解 | 高分 | **假满分**——verifier 拦不住 | 补断言或补 cap；同一捷径反复出现时改题面堵路 |
| 错误解 | 低分 | 正常 | 记录被击中的断言 id |
| 未完成 | 部分分 | 过程分正确工作 | 核对是否**依据断言**给分，而非按耗尽时间给分 |
| 答非所问 | 零分 | 正常 | — |

**假阴性禁止用删断言解决**，除非断言确实与交付要求无关。合法解被扣分说明的是断言比交付要求更窄或更死，删除会同时削弱拦错误解的能力。

**假满分是最高优先级的缺陷。** 一个被接受的错误解比十个被扣分的正确解危害大——它直接把错误行为标成正确行为写进训练数据。

### 题面回缩：压缩可行解空间

rollout 暴露的**预料之外合法解**有两种成因，必须分开处理：

- **描述缺口**：题面没有把口径、期间、范围、必需交付说清楚，模型只能猜。处置是**补题面**（补口径定义、补必需交付清单、补勾稽要求），不是把该解删掉。
- **口径本就多解**：确有多个专业上等价的处理方式。处置是**收题面**——指定业务口径（如"按母公司口径"），把它压成唯一解；或接受多解并全部枚举为合法变体。

两种处置都指向同一动作：**题面收紧，可行解空间变小**。这是把区分度做上去的主要手段——比增加断言数更有效。每收一次题面，枚举表可缩短、假阴性率下降，同时错误解的得分通道被关掉。

注意区分第三种成因：**能力不够**（模型确实做不完）不是 verifier 缺陷，不改断言、不改题面，只记入难度分布。

### 退出条件

三层，缺一层不能算收敛：

1. **必达（进验收门槛）**：枚举表每一类变体都有明确归属；**零假满分**（全部已知错误变体都被拦在阈值下）；每个合法变体得满分。
2. **统计（连续两轮稳定）**：最高分位不再上升（没有新的错误解被放过），且不再出现新的合法解变体（没有新的假阴性）。
3. **时间**：达到题包运行预算上限时仍不满足前两条的项，标为 `not_run`。**不得为了让循环结束而放宽断言。**

每轮的分诊结论写入独立的 `private/evaluation/calibration-<round>.json`，保留轮次、断言总数、reward 分布、每类计数、触发处置的具体断言语例与题面 diff。验收记录只引用最后一轮，历史轮次保留可追溯。

## 不可被套利的题面

防套利在**数据侧**与**奖励侧**两层，数据侧是根本：**拒绝本身可被利用的题**。

题面设计必须满足：

- **无隐藏要求**：题面公开的交付要求与验证器实际检查的断言集合**一一对应**。验证器检查了题面未要求的东西 = 隐藏要求 = 候选被罚了没被告知的项。
- **无测试泄漏**：解题视图不含断言、期望值、阈值或判分代码。
- **无解题捷径**：存在不完成实际工作即可通过断言的路径时，该题不得入库。典型捷径：断言只查字段存在、只比参考文件 hash、只做关键词匹配。
- **断言强到能验证自身目标**：验证器覆盖不到任务核心动作时，题不可入库。

奖励侧防护：

- 监控轮次与产物增长。断言设计若导致"拖长时间多拿分"（如按时间或按步数给分），须移除该机制。
- `S` 冻结（见聚合第 2 条）本身就是奖励侧防护：候选无法通过影响同批样本改变自己的标尺。

## 解析失败与故障

解析失败或缺交付**按实际内容给分并保留理由**；不因缺件把无关 criterion 连带判零，也不因局部可读就跳过失败项。

以下情形是 `verifier_failure`，**不产生 reward**，不伪造成候选零分或满分：

- 可信输入缺失、损坏或哈希不符；
- 评分依赖（解析库、Office 引擎、评阅通道）不可用；
- 评阅通道协议故障、响应不完整或超时；
- 断言报告缺失且终态也无法判定。

运行前清除旧 reward；只有完整有效评分才写 reward。**旧 reward 绝不能掩盖本次评分失败。**

评分器自身的启动失败、异常退出与协议故障**必须与"候选得零分"在记录上可区分**：前者不进均值的有效分母。

## 费用与故障恢复

同一任务多次评分时，将稳定的题面/输入/rubric 放在前缀，候选及动态证据放后缀，按供应商支持配置缓存边界与 TTL。以实际 cache creation/read usage 判断命中；格式稳定的测试不能证明真实跨候选命中。重复批次应按同题固定材料分组，并按实际间隔选择 TTL；一次性请求是否建缓存取决于后续复用预期。

解题与评阅的调用分开记账，保留普通输入、缓存写入、缓存读取、输出 tokens 和实际调用数；未知 usage 保持未知，价格估算与供应商账单分开。批次配置限制并发、最大轮数、阶段超时和重试次数。

若服务已完整返回但本地发布失败，可校验当前请求与保存请求完全相同、候选哈希/模型/原始完整响应一致后恢复本次评分，注明 `new_model_call=false`。恢复只复用同一次完整响应，不跳过模型评分、不使用历史答案白名单，也不把局部前缀相同当作整个请求相同。

## 机器可校验的最低要求

题包必须能让静态检查独立验证评分契约，而不必重新解读每份 rubric：

```json
{
  "scale": 24,                       // S：本题标尺，等于断言总数
  "assertions": [
    {"id": "R1.fcf-bridge",          // 稳定 id，结果断言
     "kind": "outcome",
     "unit": "现金及现金等价物净增加额桥接",
     "criterion": "R1"},
    {"id": "R2.covenant-trigger",    // 稳定 id，依据断言
     "kind": "evidence",
     "unit": "借款合同补充协议第3.2条触发判定",
     "criterion": "R2"}
  ],
  "critical_errors": [
    {"id": "CE.period", "assertion": "R1.period", "cap": 0.5}
  ]
}
```

约束：`scale` 等于 `assertions` 长度；`id` 全局唯一；`kind` 为 `outcome` 或 `evidence`；每条断言映射到一个 criterion；`critical_errors` 引用的断言 id 必须存在。**`unit` 字段是给作者自检断言独立性的**——两条断言描述同一个工作单元时必须合并。

评分器实现在 `tests/` 内，其输出 schema、聚合公式与写入路径见 [交付契约](output-contract.md)。
