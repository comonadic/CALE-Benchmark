# 从 法律 input-data 推导题目的示例

以下是方法演示，不表示这些文件已在本项目中下载或生成了真实题。

**给定材料**：采购合同、技术附件与一份补充协议，没有用户指定的问题。

1. 盘点主体、签署版本、生效时间、优先级、验收和付款条款，确认附件关联。
2. 提出候选：A 主文与附件一致性审查；B 延迟履约索赔；C 验收和付款义务日历。
3. 如果只有合同条款，没有真实履约和送达记录，排除 B；若多个附件之间存在可定位冲突，选择 A，记录 C 的可行性与未选理由。
4. agent 自主设定有材料支撑的采购方审查视角，写 instruction，要求输出 `reviewed-contract.docx` 与 `issues.xlsx`，明确修订、理由和交叉引用要求。必要商业假设公开写入 scenario。
5. 制作私有问题清单、参考修订、条款证据与 rubric；接受合理替代措辞与商业取舍。原件和假设进入输入，参考修订不进入输入。
6. 检查遗漏补充协议、主文修改但附件未改、假引文等反例，再从可见输入试解。

如果实际 input-data 只有公开判决，就改选争点/证据角色分析或裁判依据核对，不虚构合同原件或事前卷宗。最终交付完整 [题目文件夹](output-contract.md)，不是让用户先选题。
