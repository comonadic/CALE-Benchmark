# Verification contract

`test.sh` runs `verify.py` and then the offline `rubric_bridge.py`. The declared Linux environment supplies Python, LibreOffice, Poppler and libraries. Tests have no host dependency path and perform no networking.

Harbor's separate verifier skips test upload. Build the portable grader from `tests/Dockerfile` with `tests/` as its context; it uses the same pinned Python base and dependency layers as the agent environment, places trusted code at `/tests`, and embeds the exact current `tests/input-data` at `/workspace/input-data`. The agent's `environment/` context contains only visible inputs and its Dockerfile. No solution/private files or machine-local image identifier is part of either image declaration. The coordinator pins the independently built grader image when running native Harbor.

The bridge allows 1800 seconds for the actual sealed independent response, within the declared 2100-second verifier limit. `RUBRIC_WAIT_SEC` can override this for short controlled missing-response probes; response timeout remains a verifier failure with no reward.

Before even an empty submission can score0, `runtime_guard.py` verifies baked `asset-manifest.json` hashes, the complete trusted input set, script imports, the official PDF and actual LibreOffice/Poppler version calls. Source/code/import/dependency faults produce `invalid` with no reward. Then known ZIP/XLSX/DOCX parse defects are caught only around native opening APIs by `candidate_guard.py` and settle normal submission0; unexpected checker errors remain grader faults. The manifest is refreshed by authoring after an authorized change and embedded in the pinned grader, never regenerated inside a trial. Local entrypoint probes can override `TASK_INPUT_DIR`, `TASK_OUTPUT_DIR` and `VERIFIER_LOG_DIR`; native defaults remain `/workspace/input-data`, `/workspace/output` and `/logs/verifier`.

Objective technical coverage is 80 points: typed facts and units, the full historical bridge, formula provenance and upstream input perturbations, a single active scenario, both distribution bounds, budgets, all 15 sensitivity combinations, missing/zero/range boundaries and native artifact checks. `criterion-results.json` records every assertion and weighted criterion/subcriterion upper bound. Status checks verify a nonempty native status and record the actual decision cell and each recalculated case's numeric or invalid-input context; they do not assess its meaning. Source values can be signed deductions or positive expense inputs with subtraction. The visible `input-data/model-data-dictionary.md/json` defines the financial model handoff index: required workbook-scope names identify arbitrary single cells, including each sensitivity result. `tests/model-data-dictionary.json` is the matching trusted schema. No private label vocabulary, adjacent-cell search, header wording, axis distance, sheet name or coordinate determines discovery. Matrix, long-table and vertical layouts are supported. Optional positive unit multipliers explicitly convert stored monetary values to yuan and quantities to shares; omission means1. Per-unit amounts and proportions remain unscaled.

An actual independent judge reviews all seven full rubric criteria (R01-R07, total 100) using `judge-context.json` and the verified source index. This includes state meaning: any clear correct wording receives corresponding credit; incorrect actual status cannot be rescued by correct terms elsewhere. The bridge includes complete extracted inputs, actual submitted XLSX values/formulas/caches and layout metadata, DOCX current/deleted text, actual rendered DOCX pages, objective results and submitted byte hashes. No reference-answer hash whitelist or reference-text comparison is used. The host helper supplies a response bound to the sealed canonical request digest. Coverage, score ranges, judge identity, reasons, positive evidence and candidate byte binding are validated. Each final criterion is `min(objective technical upper bound + that criterion professional maximum, actual independent full criterion score)`. The 20 professional maxima are 6 for R01, 2 for R04, 10 for R06 and 2 for R07; they are never prefilled or added separately. `professional_points` remains null rather than claiming a professional-only subtotal from a full-criterion response.

Missing or empty required deliverables receive deterministic zero. Missing or malformed required business named regions (including nonexistent worksheets, multi-cell/external/constant references, local-only or duplicated names) are ordinary `invalid_submission` scored0; the bridge settles this published handoff gate without requesting professional credit. Valid mappings with wrong financial values/formulas/state meanings receive actual criterion scores. Trusted dictionary/code/source, Office execution, extraction and missing/malformed/digest-mismatched judge responses are verifier failures: `invalid`/`verifier_failed` is written and reward files are absent, because Harbor ignores the test exit code when a reward exists.

Local author challenges call `verify.py` directly to audit technical upper bounds. A normalized objective reward of 1 is not a full score, status correctness finding or model solve. Status-semantic candidates intentionally include wrong statuses with correct calculations; their requests are prepared for actual independent review and remain pending until a real response is supplied. `rubric_bridge.py --prepare-only` clears reward files and builds the canonical actual request; the reviewer must return exactly R01-R07, not the older professional subcriteria. `private/authoring/challenge_status_protocol.py` uses explicitly labeled controlled responses only to test protocol rejection and min-cap arithmetic, never to claim independent finance scores. Docker, Harbor oracle and independent solver/judge runs are separately recorded in private validation. The old `finalize_package.py` is an archived authoring generator that predates canonical lineage and this repair; do not rerun it.
